# 生产级改进规约：从演示级到内部生产

> 版本：v1.0 ｜ 日期：2026-09-19 ｜ 状态：待评审
> 范围：drone-agent001 三端（agt_python:8000 / agt_backend:8080 / agt_web:9090）+ 部署形态
> 依据：生产就绪度评估（2026-09-19，逐项代码核实）+ `docs/specs/改进路线图.md`
> 定位口径：**演示级（现状）→ 内部生产（本规约目标）→ 规模化生产（只划边界，不展开）**

---

## §1 为什么需要这份规约

功能闭环（RAG / 编排 / 记忆 / 数据中台 / 治理）已经完整，但按"能不能给真实用户用"衡量，
存在六项硬缺口（2026-09-19 核实）与四项安全增强。本规约把两份输入——生产就绪度评估的
6 个 blocker 与改进路线图的 P1 项——合并成分期任务，作为实施与验收的唯一依据。

**三档口径**（避免"生产级"一词被滥用）：

| 档位 | 定义 | 现状 |
|---|---|---|
| 演示级 | 单机、自己人点开看 | ✅ 已达标 |
| **内部生产** | 小团队真实使用：可信内网、数据不丢、故障有人知道 | ⬜ 本规约目标，约 2~3 周 |
| 规模化生产 | 多实例、公网、SLA | ⬜ 需架构改造（§7 只划边界） |

## §2 现状与差距（核实过的事实，实施前须复核）

## §3 分期任务与验收标准

### S-1 服务间信任边界（P0，半天）— 差距 A ✅ 2026-09-24 已落地

**改动点**
- [x] `agt_python` 新增鉴权中间件：除 `/v1/health` 与 `/docs` 外全部要求请求头 `X-Agent-Key`，值与 `settings.agent_shared_key` 全等比对；**不匹配返回 4010**（沿用会话过期码，Java 前端已有处理）；校验失败落 `fault_event`（新增 `PATH_AUTH_KEY_REJECTED`）
      · 实现 `app/core/auth.py`：**纯 ASGI 中间件**（不用 `BaseHTTPMiddleware`——它会包 anyio 流并复制 contextvars，对 SSE 有副作用）；`hmac.compare_digest` 比对；豁免清单另含 `/`、`/redoc`、`/openapi.json`
- [x] `config.py` 新增 `agent_shared_key: str = ""`——为空时**拒绝启动**（fail-closed，防带空密钥上线）
      · 校验点在 `app/main.py` **模块级**：uvicorn 加载 `app.main:app` 即失败，比"服务起来了、首个请求才 4010"更早暴露部署错误
- [x] `agt_backend` `AgentClient.java` 所有出站请求统一加 `X-Agent-Key` 头（值走环境变量注入，不进代码库）
      · ⚠️ 实施时发现 Java 侧直连 Python 的出口**有三个**（另含 `KbClient` 知识库、`GovernanceClient` 治理），已统一收口到新增的 `AgentAuth.withKey(...)`；漏掉任一出口的表现是该业务域整体 4010
- [x] 固化启动命令改绑 `127.0.0.1`（Python 只服务本机 Java）
      · `config.host` 默认值与计划任务参数同步；8080 改用 `deploy/start-backend.cmd`（从 `deploy/secrets/agent.key` 注入环境变量）
- [x] `.env.example` 补 `AGENT_SHARED_KEY=` 示例与生成说明（`python -c "import secrets; print(secrets.token_urlsafe(32))"`）

**验收标准**
- [x] 单测：无 key / 错 key → 4010 且落一条 `auth_key_rejected`；对 key → 放行；`/v1/health` 无 key 可达（`tests/test_auth_shared_key.py`，10 项全过）
- [x] `agent_shared_key` 为空时服务拒绝启动
- [x] 真机：Java 层全链路（登录→聊天→画像）不受影响；直连 8000 无 key 被拒
- [x] `netstat` 确认 8000 只监听 127.0.0.1

**实施记录**：见 `DEV_ISSUES.md` §6.72——含三个出站出口的排查、
`.cmd` 的 CRLF 与括号两个坑、以及「8080 令牌头是 `Authorization: Bearer` 而非 `X-Token`」的口径澄清。

### S-2 前端生产构建 + nginx 托管（P0，半天）— 差距 B

**改动点**

- [ ] 9090 dev server 保留为开发模式；生产入口 = nginx 端口

**验收标准**

## §4 接口与配置契约

```
请求头（新增）：
  X-Agent-Key: <共享密钥>          # Java→Python 全部请求；Python 中间件校验

环境变量（新增，均不入库）：
  AGENT_SHARED_KEY=<token_urlsafe(32)>   # 空 = 拒绝启动
  ALERT_WEBHOOK_URL=                     # 空 = 告警关闭

nginx 路由表：
  /            → agt_web/dist（try_files fallback index.html）
  /api/*       → 127.0.0.1:8080（SSE: proxy_buffering off）
  /v1/*        → 仅本机访问，不走外网（S-1 后 8000 绑 127.0.0.1）

备份目录：
  agt_python/data/backups/YYYY-MM-DD/{session_memory,user_profile,observability,governance}.db
  保留 14 份，滚动只删 backups/ 内目录
```

## §6 铁律

1. **fail-closed 只用于鉴权，fail-open 只用于增强**：S-1 密钥校验失败必须拒绝（安全类）；
   S-6/S-7/S-8（告警/检测/脱敏）任何异常只降级计数，不阻断主链路（对齐全链路容错规约）。
2. **密钥与证书不入库**：全部走 env / nginx 本地文件；`.env` 已被 git 忽略，保持。
3. **备份只增不删业务数据**：滚动删除仅限 `data/backups/` 自建目录，不得触碰任何业务库。
4. **8060 jsdstu-3 只包装不改**：进程守护只负责拉起，源码零改动。
5. **每项验收以"能证明的方式"复核**（curl / netstat / 单测），不信工具回执（§6.64 教训）。
6. **git 提交等用户明确开口**（既有约定）。

## §7 规模化生产边界（只划界，不展开）

进入"多实例 + 公网"前必须完成，**当前单机定位下不做**：
SQLite → MySQL/PG（三库迁移 + 迁移脚本）；进程内缓存与 scheduler 外置（Redis / 独立 worker）；
uvicorn 多 worker + 反向代理负载均衡；Milvus 高可用；完整 RBAC 审计与操作留痕；
压测基线（并发/长会话/大知识库）与 SLA 定义。
