# 全链路容错规约：重试、降级、兜底与熔断

> 版本：v1.0 ｜ 日期：2026-09-18 ｜ 状态：待评审
> 范围：drone-agent001 全链路（RAG 知识库 + Agent 多智能体编排 + 业务工具调用 + SSE/网关）
> 第一目标：**测试与真实运行绝不陷入死循环**——先止血，再谈优雅。

---

## §1 为什么需要这份规约

P0/P1 落地后，三模式（REACT / PLAN / 多智能体）已全绿，但验收全部是"顺利路径 +
有限异常"。参照 open-agent-master 的实际教训（《Agent全链路容错设计.md》：语义过滤
静默降级持续数月无人察觉），容错能力缺位的典型症状是：

1. 模型同工具同参数反复调用 → token 烧干、测试卡死（**当前 agent_loop 无循环指纹防护**）；
2. 某工具持续故障（jsdstu-3 停机）→ 模型每步都试、每步都败，循环走满 max_steps 才停；
3. LLM 主模型故障 → 只能等兜底文案，无 failover；
4. 降级发生但无计数无日志 → 测试误以为一切正常。

本规约把四个概念、逐层策略、配置、验收一次定清，作为后续实现与 e2e 的依据。

## §2 四个概念的边界（沿用 open-agent 定义，换成本项目实例）

| 概念 | 触发条件 | 行为 | 恢复方式 | 本项目实例 |
|------|---------|------|---------|-----------|
| **重试 Retry** | 瞬时故障（网络抖动、429、5xx） | 同一资源原样重发 | 自动，退避后 | llm.py 对 429/5xx/网络类重试 ≤2 次，退避 2s/4s |
| **降级 Degrade** | 增强能力不可用 | 功能减弱但主流程继续 | 自动，恢复后升回 | RAG 检索失败→降级闲聊并声明；judge 失败→skipped 继续生成 |
| **兜底 Fallback** | 主路径完全不可用 | 切备选路径或返回安全结果 | 自动，常需人工升回 | AgentLoop LLMError→固定话术；PLAN 失败→降级 REACT |
| **熔断 Circuit Breaker** | 反复失败/资源滥用 | 主动切断该路径快速失败 | 冷却期后半开探测 | max_steps=6 循环熔断；本规约新增：同调用指纹、单工具连续失败、LLM provider 冷却(P2) |

一句话：重试是"再试一次"，降级是"退而求其次"，兜底是"换条路走"，熔断是"先止血别再打了"。

## §6 逐层容错策略

### 6.1 AgentLoop 控制流——防死循环主战场（对应 G1~G4）

**（1）循环指纹分级熔断**（借 open-agent LoopDetector 分级语义）：

- 指纹 = `sha1(tool_name + json.dumps(args, sort_keys=True))`，会话内滚动窗口记录；
- 第 1 次出现：正常执行；
- 第 2 次同指纹：**执行但在 tool 结果前追加一行提醒**——
  `"⚠️ 你已经用完全相同的参数调用过 {tool}，结果不会变化；请换参数、换工具，或直接汇总作答"`；
- 第 3 次同指纹：**拒绝执行**，回填
  `{"error": "同参数重复调用已被熔断，请基于已有结果作答"}`，并强制把该轮 LLM 调用改为
  不带 tools_schema（见下条"熔断恢复"）；
- 指纹窗口按会话清理（随 session_memory 生命周期），跨轮次也生效——同会话第 N 条消息里
  重复昨天的调用同样触发（防止用户反复追问同一问题导致的隐性循环）。

**（2）熔断必带恢复路径**（借 open-agent：断不是目的，软着陆才是）：

- 同指纹第 3 次触发后，本轮直接进入收尾：调一次**不带 tools_schema** 的 LLM，
  system 注入"你已收集到以下工具结果，请基于它们给用户阶段性结论"；
- 收尾成功 → 正常返回（内容可入历史，属真实产出）；收尾也失败 → 熔断说明文案（不入历史）；
- PLAN 模式下收尾时把已完成步骤标注"done"、未完成标注"skipped"回填 plan 字段。

**（3）单工具连续失败熔断**（补齐 docstring 已声称的能力）：

- 计数器按 (会话, 工具名) 记录连续失败次数（BizError/超时/网络异常都算，TypeError 传参
  错误不算——那是模型自愈范畴）；
- 连续失败 ≥ `agent_tool_fail_max`(默认 3) → 该工具在本轮剩余步骤直接熔断：
  不再执行，回填 `{"error": "工具 {tool} 已连续失败 3 次，疑似服务故障，请停止调用它"}`；
- 熔断后模型若给最终回答，正常收尾；若仍在调工具，走 max_steps 熔断收尾。

**（4）工具执行超时兜底**：

- `registry.execute` 一律包 `asyncio.wait_for(..., timeout=settings.agent_tool_timeout)`
  （默认 15s，覆盖 jsdstu_timeout=10s 与并行 gather 场景）；
- 超时按一次"失败"计入 (3) 的计数器；回填 `{"error": "工具执行超时(15s)"}`；
- 并行 gather 的总超时 = 单工具超时 + 5s 余量，整组超时不熔断、逐个按超时处理。

**（5）max_steps 熔断保持现状**（6 步，超限 finalize 收尾、如实告知用户改问法）。

### 6.2 LLM 调用层

| 问题 | 策略 | 做法 |
|------|------|------|
| 429/5xx/网络抖动 | 重试 | 现状保留：≤2 次、退避 2s/4s；4xx（除429）不重试 |
| 主模型持续故障 | 兜底 | LLMError → 各层固定话术（AgentLoop/RAG judge/路由各自已有）；话术**不入会话历史**（§6.9） |
| 单 provider 反复失败拖垮响应 | 熔断（P2） | 引入 provider 链（deepseek 主 → glm-4-flash 备）时同步实现 cooldownUntil（默认 300s），冷却期内跳过、到期半开探测 |
| 输出超长 | 降级 | 最终回复 max_tokens 限制保持现状；工具输出 3000 字符截断保持现状 |

P2 之前的过渡事实：单 provider 挂 = 全链兜底话术。可接受（开发期），上线前必须做 G8。

### 6.3 RAG 知识库链路

现状已达标，规约化固化 + 一条新增：

| 环节 | 故障 | 策略 | 做法（现状固化） |
|------|------|------|------|
| 检索 | Milvus/GLM embedding 挂 | 降级+声明 | decision=degraded → 降级闲聊，回复中如实说明知识库暂不可用（绝不假装检索到了） |
| 检索 | 跨域问题 | 兜底 | **确定性拒答文案**，绝不降级给闲聊人设（实测会编造菜谱/游戏名） |
| judge | LLM 调用/解析失败 | 降级 | judged=skipped，继续生成，由生成端"无证据不陈述"硬约束兜住 |
| 生成 | LLM 失败 | 兜底 | 固定话术，不入历史 |
| 降级可见性 | 静默降级（G6） | **新增** | degraded/skipped 已在 decision 字段透出到前端——P1 起增加计数（§8） |

### 6.4 多智能体（subagent）

现状已达标，固化 + 两处收紧：

| 问题 | 策略 | 做法 |
|------|------|------|
| 子智能体内部死循环 | 熔断 | 子循环继承主循环全部防护：同指纹分级熔断 + 子级 max-turns（定义文件 max-turns）+ 工具超时——**子智能体不是法外之地** |
| 子智能体超时 | 兜底 | wait_for → TIMEOUT + 黑板"该专家未完成，以下仅为主循环已有信息"（现状保留） |
| 委派预算耗尽 | 熔断 | 会话 10 次上限，超限明确拒绝并列出已完成专家（现状保留） |
| 黑板污染 | 守卫 | 兜底话术/TIMEOUT 说明可入黑板（用于防重复委派），但主循环汇总时必须在回复中声明"该专家未完成"——不允许把未完成说成已完成 |
| 委派失败（定义文件缺失/未知名字） | 兜底 | 拒绝并列出可用专家名单（现状保留） |
| 子智能体幻觉已写库 | 预防 | 白名单强制只读（danger 剔除）保持不变；子智能体 prompt 首行声明"你是只读分析角色，无写权限" |

### 6.5 业务工具调用

| 问题 | 策略 | 做法 |
|------|------|------|
| 业务错误（权限/不存在/4011） | 自愈 | BizError 结构化回填，模型如实转述（现状保留，不重试） |
| 登录过期 4010 | 终止 | BizAuthError 整轮终止 → 引导重登录固定话术（现状保留） |
| 瞬时网络抖动（查询类） | 重试（P2，G7/G9） | 引入前维持"回填自愈"；引入时必须带 `is_idempotent` 属性：查询类 true 自动重试 1 次，写操作 false 绝不自动重试（写操作有确认门，重试发生在确认之后也必须走指纹去重） |
| 非幂等重复提交 | 预防 | 确认门执行 + §6.1 指纹去重天然覆盖：同会话同参数写操作第二次出现直接拒绝 |
| 媒体上传大文件 | 超时 | upload 独立 120s 超时（现状保留），且不受 agent_tool_timeout=15s 约束（wait_for 取工具级覆盖值） |

### 6.6 写操作确认门（与容错的交叉规则）

- 确认门拦截本身不算"失败"，不进任何熔断计数；
- 用户确认后执行阶段若遇瞬时网络错误：**不自动重试**，回填错误让用户决定是否再确认一次
  （宁可让用户多点一次确认，不可自动重发写请求）；
- 确认动作的会话残留（pending_store）带 TTL（现状），过期后确认无效需重新发起——防"昨天的确认今天生效"。

### 6.7 SSE 流式与 Java 网关

| 问题 | 策略 | 做法 | 期 |
|------|------|------|----|
| Python 非流式分支异常 | 透传 | error 事件（现状） | 已有 |
| Java→Python 无显式超时 | 预防 | WebClient/RestTemplate 显式 read timeout（60s，> llm_timeout=60s 需重新核定分层，见 §7） | P2(G10) |
| SSE 中途断流 | 兜底 | 前端已收内容展示 + 重试提示（现状前端已有 error 分支，固化） | 已有 |

### 6.8 会话历史写入守卫（G5，防兜底文案中毒）

**判定规则**（实现于 agent_service 写历史入口，一条函数）：

- 不入历史的回复：LLMError 兜底话术、4010 重登录引导、熔断说明文案、降级闲聊的
  "知识库暂不可用"声明轮（该轮用户问题保留，assistant 内容不入）；
- 判定依据：sentinel 常量表（各兜底话术定义为模块级常量，写历史时比对），不做模糊匹配；
- 可入历史：正常 RAG 回答、业务回答、熔断恢复的阶段性汇总（真实产出）、确认门复述
  （维持上下文连贯必需）。

## §7 超时分层总表（外层 > 内层，铁律 7）

| 层 | 超时 | 说明 |
|----|------|------|
| jsdstu 业务接口（单工具内部） | 10s（upload 120s） | 现状 |
| 工具执行 wait_for | 15s（工具级可覆盖） | 新增 G4，> 10s 内层 |
| 并行 gather 整组 | 20s | 单工具超时 + 余量 |
| LLM 单次调用 | 60s | 现状 llm_timeout |
| LLM 重试序列 | ≤ 60×3 + 退避 ≈ 190s | 重试耗尽即 LLMError |
| 子智能体 wait_for | 按定义文件 timeout-seconds（60s 默认） | 含其内部多次 LLM+工具——**注意：60s 内含 LLM 60s 是临界值，子智能体定义统一改为 timeout-seconds ≥ 90 或 LLM 失败直接终止子循环**，实现时二选一，禁止外层 ≤ 内层 |
| 整个请求（Java 侧 read timeout） | 240s | P2 落地 G10 时核定，> LLM 重试序列 + 工具序列 |

## §8 可观测性：降级必须计数（G6，衔接数据中台）

三条铁律（沿 open-agent）：

1. **降级必须计数**：每个降级/熔断路径一个计数点，落 `data/metrics/fault_counters.json`
   （进程内累计 + 定期落盘，数据中台埋点上线后迁 MySQL，接口约定按《业务操作全能力规约》§10）。
   维度：`{path, event, session_id, ts, detail}`；path ∈ rag_degraded / rag_refused /
   plan_degraded / plan_replan / loop_fingerprint_warn / loop_fingerprint_break /
   tool_fail_break / subagent_timeout / subagent_budget_exhausted / llm_fallback
   （以上为 P2 基线；后续补充：tool_timeout / llm_failover / reply_cleaned）。
   `reply_cleaned`（P2+，DEV_ISSUES §6.56）= 正文开头漏出英文思考句、已被确定性剥离——
   它**不改变回答内容**，只记录「提示词没约束住、兜底接住了」的频次：
   计数持续增长说明提示词该再收紧（兜底是网，不是解药）。
   **覆盖两条产出路径**（§6.57 补齐流式）：同步整段走 `_clean_reply`；RAG / 闲聊的
   逐字流式走 `LeadThoughtStreamGuard`（首段缓冲，判定内核与同步同为 `_analyze`）。
   流式那侧的意义不止"用户看不到脏开头"——它同时保证**写回会话历史的是净化后文本**，
   否则脏数据会被模型在后续轮次里模仿（泄漏自我强化）。
2. **降级必须留痕**：WARN 级日志，格式固定 `"本应 X，实际 Y（原因 Z）"`。
3. **熔断必须可见**：fingerprint 熔断、工具连续失败熔断、TIMEOUT 三类必须 WARN+。
   前端执行过程区（toolTrace）已能展示 blocked/error，天然是"用户侧可见"。

## §9 工程原则清单（评审后即团队规范）

1. 重试仅限瞬时 + 仅限幂等；写操作永不自动重试。
2. 失败方向向上兼容：路由判不准按复杂处理（PLAN），绝不按简单跳过工具。
3. 降级要有声明：缺什么对模型说、对用户说，绝不假装正常。
4. 兜底文案不入会话历史（§6.8 sentinel 表）。
5. 熔断必带恢复路径：同指纹熔断后无工具纯生成收尾，交付阶段性结论优于抛异常。
6. 熔断不惩罚确认门：确认门拦截与熔断计数完全隔离。
7. 超时外层 > 内层（§7 表为准，改动任何一层必须复核全表）。
8. 每个降级路径配一个计数点；没有指标的降级等于没有降级。
9. 子智能体继承主循环全部循环防护，只读白名单不可绕过。
10. docstring 必须与实现一致（G3 教训：文档声称的防护会让人误判已兜底）。

## §11 e2e 验收标准（`biz_fault_tolerance_e2e.py`，全部进程内 stub，不依赖真实 LLM/服务）

| # | 用例 | 断言 |
|---|------|------|
| 1 | 同工具同参数连续 3 轮 | 第 1 次执行、第 2 次执行且结果含提醒、第 3 次拒绝且触发收尾，最终回复为阶段性汇总 |
| 2 | 同指纹跨消息重复 | 第 2 条消息里同指纹直接拒绝（会话级窗口生效） |
| 3 | 工具连续失败（stub 工具恒抛 BizError） | 第 3 次失败后同轮后续调用被拒，回填"疑似服务故障" |
| 4 | 工具卡死（stub sleep 超时） | 15s（用例中调小）wait_for 触发，计失败一次 |
| 5 | max_steps 熔断 | 模型 6 步仍调工具 → finalize 收尾，回复含改问法引导 |
| 6 | 兜底文案不入历史 | stub LLM 首轮抛 LLMError、次轮正常 → 历史中无兜底话术，但用户问题保留 |
| 7 | 子智能体超时/预算/白名单 | 回归现有 E 段断言不回退 |
| 8 | 计数器 | 上述每条触发后对应 fault_counters 维度 +1 |
| 9 | 确认门不受熔断影响 | 同参数写操作被确认门拦截 3 次不触发指纹熔断（拦截≠执行） |
