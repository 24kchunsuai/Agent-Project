# Spec：数据库设计规约

> 版本：v1.0（2026-09-18）
> 范围：drone-agent001 自有数据存储——`observability.db`（埋点）、`governance.db`（语料治理，详见语料治理规约 §3，本文不重复）、评测产物与 JSON 账本；以及未来迁 MySQL 的映射规范。
> 不在范围：jsdstu-3 业务库（他人系统，只读调用）；Milvus 向量库（见语料治理规约）。

---

## 1. 存储格局总览

| 库 | 引擎 | 位置 | 归属 | 生命周期 |
|---|---|---|---|---|
| observability.db | SQLite | `agt_python/data/metrics/` | 数据中台（本规约主对象） | 明细 TTL 归档，预聚合长期保留 |
| governance.db | SQLite | `agt_python/data/governance/` | 语料治理 | 长期 |
| fault_counters.json | JSON | `agt_python/data/metrics/` | 内存计数器落盘 | 随进程 |
| eval 产物（questions/biz_questions/report） | JSONL/JSON | `agt_python/data/kb/eval/` | 评测 | 长期，git 外 |

选型原则（延续语料治理规约决策 1）：**单机、嵌入式、零运维 → SQLite**；跨库联查/多人并发分析需求出现后再迁 MySQL（§7）。

## 2. 通用规约（所有库遵守）

1. **命名**：表名蛇形小写复数语义（`agent_chat_log`）；索引 `idx_<表>_<列>`，唯一约束 `uk_<表>_<列>`；字段蛇形小写。
2. **主键**：`id INTEGER PRIMARY KEY AUTOINCREMENT`；SQLite 场景跨表无外键（应用层保证），MySQL 迁移后同样**不用物理外键**（与 AgentCraft init.sql 风格一致，理由：埋点数据允许孤儿行，物理外键反成写入负担）。
3. **时间**：
   - 现状：`created_at TEXT`，本地时间 ISO8601（秒级，`datetime.now().isoformat()`）；
   - **约定**：单机部署期维持本地时间（东八区），所有聚合 SQL 必须用 `datetime('now','localtime',…)` 基准（现状如此）；**禁止混用 UTC 与本地时间**；
   - 迁 MySQL 时统一转 `DATETIME` 并在迁移脚本中显式声明时区口径（数据库不存时区，口径写进表 COMMENT）。
4. **布尔**：`INTEGER 0/1`（ok/degraded），不用 SQLite 的 TRUE/FALSE 字面量。
5. **可空性**：埋点字段尽量给默认值（`DEFAULT 0 / DEFAULT ''`），写入端永不传 NULL。
6. **演进三规则**：
   - 只加列、不删列、不改列义（废弃列注释标记 `-- deprecated 2026-xx-xx`，物理删除留到 MySQL 迁移时）；
   - 每个库维护 `schema_version(version INTEGER, applied_at TEXT)` 表，迁移函数按版本号幂等执行（P1 引入，迁移=加列+建索引，都支持 IF NOT EXISTS 语义）；
   - 迁移失败 fail-fast 拒绝启动（与工具 manifest 双向校验同一哲学）。

## 3. observability.db 现状 DDL（事实基准，改动须同步本规约）

```sql
CREATE TABLE IF NOT EXISTS agent_chat_log(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    trace_id TEXT, session_id TEXT, user_id INTEGER, permission TEXT,
    intent TEXT, intent_source TEXT, mode TEXT, model TEXT,
    prompt_tokens INTEGER DEFAULT 0, completion_tokens INTEGER DEFAULT 0,
    duration_ms REAL, ok INTEGER DEFAULT 1, degraded INTEGER DEFAULT 0,
    content_chars INTEGER DEFAULT 0, error TEXT DEFAULT '',
    created_at TEXT);
CREATE TABLE IF NOT EXISTS agent_tool_call(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    trace_id TEXT, session_id TEXT, step INTEGER, tool TEXT,
    ok INTEGER DEFAULT 1, blocked TEXT DEFAULT '', error TEXT DEFAULT '',
    duration_ms REAL, args_digest TEXT DEFAULT '', created_at TEXT);
CREATE TABLE IF NOT EXISTS agent_delegation(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    trace_id TEXT, session_id TEXT, agent TEXT, status TEXT,
    duration_ms REAL, created_at TEXT);
CREATE TABLE IF NOT EXISTS fault_event(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    path TEXT, session_id TEXT, detail TEXT, created_at TEXT);
-- 2026-09-18 P0：fault_event 加列 trace_id TEXT DEFAULT ''（ALTER 迁移，见 §3.1）
CREATE INDEX IF NOT EXISTS idx_chat_created ON agent_chat_log(created_at);
CREATE INDEX IF NOT EXISTS idx_fault_created ON fault_event(created_at);
-- 2026-09-18 P0 新增（用途见 §3.1 修复清单）：
CREATE INDEX IF NOT EXISTS idx_tool_created ON agent_tool_call(created_at);
CREATE INDEX IF NOT EXISTS idx_delegation_created ON agent_delegation(created_at);
CREATE INDEX IF NOT EXISTS idx_chat_trace ON agent_chat_log(trace_id);
CREATE INDEX IF NOT EXISTS idx_tool_trace ON agent_tool_call(trace_id);
CREATE INDEX IF NOT EXISTS idx_delegation_trace ON agent_delegation(trace_id);
CREATE INDEX IF NOT EXISTS idx_fault_trace ON fault_event(trace_id);
```

### 3.1 缺口修复状态（2026-09-18 P0 更新）

| 缺口 | 影响 | 状态 |
|---|---|---|
| fault_event 无 trace_id | 故障无法关联回会话轨迹 | ✅ P0 已修复：`ALTER TABLE fault_event ADD COLUMN trace_id TEXT DEFAULT ''`（迁移幂等，存量行保留）；record_fault 从 ContextVar 取 trace_id，聊天上下文外为空串 |
| agent_tool_call / agent_delegation 无 created_at 索引 | 24h 聚合全表扫 | ✅ P0 已建 `idx_tool_created` / `idx_delegation_created` |
| 全库无 trace_id 索引 | trace 追溯接口按 trace 查四表全表扫 | ✅ P0 已建 `idx_chat_trace` / `idx_tool_trace` / `idx_delegation_trace` / `idx_fault_trace`（四条 trace 索引支撑 `/metrics/traces/{id}`） |
| agent_chat_log 无 session 索引 | 会话视图按 session 过滤慢 | P1 视实际数据量决定（现有查询走 created_at 索引后量级可控） |

迁移实现注意（已实测）：**加列必须发生在建 trace 类索引之前**——存量旧库上先建 `idx_fault_trace` 会因列不存在而失败；现 `_ensure_conn()` 顺序为 建表 → ALTER 加列 → 建索引。

索引代价说明：四表均为写入频繁的 append-only 表，每加一个索引写放大约 +1 次页写；以上数量可控（≤8 个），不再多加——**每新增索引必须在本文登记并写明用途**。

### 3.2 数据红线（与开发规约 §4.2 一致）

明细表禁止出现 prompt 原文、回复原文、token 凭据、完整业务对象。`args_digest` 仅摘要哈希。评测/调试数据不得写进本库（测试用 `DATA_ROOT` 隔离目录）。

## 4. DWS 预聚合表（P1 新增）

```sql
CREATE TABLE IF NOT EXISTS metrics_daily(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    day TEXT NOT NULL,              -- 'YYYY-MM-DD'（本地日期）
    metric TEXT NOT NULL,           -- 指标名，白名单：chat_total/chat_failed/chat_degraded/
                                    -- tool_total/tool_failed/delegation_total/delegation_done/
                                    -- fault_total/duration_avg/duration_p95/tokens_total
    dim TEXT NOT NULL DEFAULT '',   -- 维度值：intent / tool / agent / fault_path / model，空=全量
    dim_type TEXT NOT NULL DEFAULT '', -- P1 落地时登记的扩展列：dim 所属维度域（''/intent/model/
                                       -- tool/agent/fault_path），使 timeseries 的 groupBy 可
                                       -- 区分同名维度值；全量行 dim='' 且 dim_type=''
    value REAL NOT NULL DEFAULT 0,
    updated_at TEXT,
    UNIQUE(day, metric, dim));
CREATE INDEX IF NOT EXISTS idx_metrics_daily_day ON metrics_daily(day, metric);
```

> P1 落地记录（2026-09-18）：表已按上文创建（含 dim_type 扩展列，原因见列注释）；重算实现为**先删后插**（比 INSERT OR REPLACE 多一层保障：维度当天归零时不留陈旧行），幂等可重跑；定时重算近 2 天（`metrics_recompute_seconds`，默认 600s）+ 查询时历史天懒补算 + 今天强制重算。

- 生成方式：**定时重算**（幂等，`INSERT OR REPLACE`），挂现有 scheduler（与对账/巡检同机制），每 10 分钟重算近 2 天，历史天首次访问懒补算；
- 明细 TTL 归档后（§6），DWS 是历史趋势的唯一数据源——因此**明细删除窗口（90 天）必须 ≥ 看板最大回溯窗口**；
- 禁止在 metrics_daily 上再做二次聚合表（三层封顶：ODS→DWS→看板）。

## 4.1 反馈闭环两表（P2 新增，2026-09-19）

```sql
-- 事件表（第五张）：只存元数据，与四表同风格，只增不改
CREATE TABLE IF NOT EXISTS agent_feedback(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    trace_id TEXT NOT NULL, session_id TEXT DEFAULT '',
    user_id INTEGER DEFAULT 0, rating TEXT NOT NULL,   -- 二值：'up'/'down'（规约开放问题 2 拍板）
    comment TEXT DEFAULT '', created_at TEXT);          -- comment 存摘要 ≤200 字符
CREATE INDEX IF NOT EXISTS idx_feedback_trace ON agent_feedback(trace_id);
CREATE INDEX IF NOT EXISTS idx_feedback_created ON agent_feedback(created_at);

-- 独立内容表（数据中台规约 §4.2 口子：显式开关 + TTL，绝不并入四表）
CREATE TABLE IF NOT EXISTS feedback_content(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    trace_id TEXT NOT NULL,
    question TEXT DEFAULT '',      -- 来自会话记忆最后一轮（截断 2000 字符）；记忆不在则留空
    answer TEXT DEFAULT '', created_at TEXT);
```

> P2 落地记录（2026-09-19）：schema_version 升 **v3**；内容表受 `feedback_capture_content`（默认 true）控制，TTL=`feedback_content_ttl_days`（默认 30 天）由 DWS 重算循环搭车清理；同一 trace 重复反馈=新事件（只增不改），列表/候选取最新；金标集候选由 `/metrics/feedback/export` 导出 JSONL，**不自动写入 eval 目录**。

## 5. 写入与读取规约

- **写入**：只允许 telemetry 批量写（5s flush，单连接 + 锁）；任何绕过 telemetry 直连 observability.db 的代码视为违规；
- **读取**：查询接口只读（Python sqlite3 只读打开或同一连接 SELECT）；长查询必须带时间边界，禁止无 WHERE 的全表 SELECT 进 API；
- **异常口径**：存储异常只记日志不抛出（读侧返回 `enabled:false` 或空集），与容错规约"埋点永不伤业务"一致；
- **时钟坑**：`created_at` 为字符串比较，必须保证写入端格式统一（`isoformat()` 秒级、无时区后缀）。若未来引入毫秒或时区后缀，聚合 SQL 全部失效——改动前先查本条。

## 6. 保留策略（TTL）

| 数据 | 保留 | 清理方式 |
|---|---|---|
| 四表明细 | 90 天 | scheduler 每日删 `created_at < now-90d`，分批（每批 5000 行）避免长锁 |
| agent_feedback | 90 天（随四表明细同窗口） | 未实现（P2 量小，挂 scheduler 待四表 TTL 一起做） |
| feedback_content | `feedback_content_ttl_days`（默认 30 天） | DWS 重算循环搭车清理（规约 §4.2：内容类必须带定时清理） |
| metrics_daily | 永久 | — |
| fault_counters.json | 随进程重启重置（内存真源） | — |
| 触发 VACUUM | 不自动 | 手工执行（SQLite VACUUM 需独占，只能在停服务窗口做），库体积 > 200MB 时提示 |

## 7. MySQL 迁移映射（触发条件见容错规约 §13 / 开发规约 §8 P3）

### 7.1 触发条件（满足其一）

1. 看板需要 join jsdstu 业务库（跨库联查）；
2. 多实例部署（SQLite 单文件不可共享）；
3. 单表日增 > 50 万行且查询 p95 劣化。

### 7.2 类型与命名映射

| SQLite | MySQL 8.0 | 备注 |
|---|---|---|
| INTEGER PRIMARY KEY AUTOINCREMENT | BIGINT NOT NULL AUTO_INCREMENT | 主键 |
| TEXT（时间） | DATETIME DEFAULT CURRENT_TIMESTAMP | 迁移脚本显式转时区口径 |
| TEXT（枚举/短文本） | VARCHAR(64) + COMMENT | intent/mode/status/path 均定长枚举 |
| TEXT（错误详情） | VARCHAR(512) | 超长截断 |
| REAL | DOUBLE | duration_ms |
| INTEGER 0/1 | TINYINT(1) | ok/degraded |

建表规范对齐 AgentCraft：`ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci`，表与列全带 COMMENT，索引沿用 `idx_/uk_` 前缀；DDL 统一放 `agt_backend/sql/`（或 `sql/metrics_*.sql`），**禁止只在代码里建表**——MySQL 下 DDL 即文档。

### 7.3 迁移步骤（一次性脚本，人工执行）

1. 停写（停 8000）→ 2. SQLite 全量导出 → 3. 类型转换导入 MySQL → 4. 双读对账（同一批聚合 SQL 在两库结果一致，抽样 ≥3 天）→ 5. 切读 → 6. 观察一个周期后 SQLite 转归档只读，禁止双写长期化。
