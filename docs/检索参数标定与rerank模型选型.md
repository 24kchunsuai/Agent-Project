## 二、切片策略与实测调参

### 2.1 最终策略（5 步）

1. **标题感知**：先按 markdown 标题切段，贴合文档结构
2. **碎片合并**：段落 < 200 字且与前片合并后 ≤ 600 字时合并
3. **中文递归**：超长段落按「段 → 行 → 句 → 逗号 → 空格」优先级逐级下探
4. **标题前缀注入**：每片正文前拼 `【文档标题】「章节标题」`，让切片自带上下文
5. **重叠**：相邻片保留 80 字符重叠，避免答案被切断在边界

### 2.2 碎片合并的效果（实测）

| 版本 | chunk 数 |
|---|---|
| 无合并 | 1593 |
| **有合并（MIN_CHUNK=200）** | **934** |

第三方技术文档标题极密（「## 一、概述」下常只有一两句话），不合并会产生大量
50~150 字的碎片：信息量不足、语义模糊，反而拉低召回，还无谓放大候选池。

### 2.3 切片长度：600 字最优（反直觉，但有数据）

诊断实验固定同一批候选，只改文本长度：

| 切片长度 | 分数跨度 | 期望文档排名 |
|---|---|---|
| **原样（≈700 字）** | 0.997907 | **#1** ✅ |
| 截断 300 字 | 0.996843 | #3 |
| 截断 120 字 | 0.866951 | #2 |

**结论：切片不宜缩短。** 完整切片语义更完整，rerank 判断反而更准。
（这推翻了我先前"短切片利于 rerank 精度"的猜想。）

## 三、⭐ 核心发现：rerank 模型选型决定一切

### 3.1 两个模型的行为差异（实测）

同一批测试，query = 「微型无人机的重量上限是多少？」

| 模型 | 相关文档得分 | 无关文档得分（红烧肉做法） |
|---|---|---|
| `rerank` | 1.0 | **0.861188** |
| **`rerank-pro`** | 0.999542 | **0.000003** |

基础版 `rerank` 给**完全跨域**的文档打 0.86 分——它的分数几乎不携带区分信息。

### 3.2 真实规模下的表现（934 chunk，top20 候选）

| 指标 | `rerank`（错） | `rerank-pro`（对） |
|---|---|---|
| 分数范围 | 0.999993 ~ 1.000000 | **0.0014 ~ 0.9994** |
| 分数跨度 | 0.000007 | **0.997966** |
| 全量 800 候选标准差 | 0.000002 | **0.400502** |
| 期望文档排名 | #5 | **#1** |
| top1 命中率 | 0 / 40（0%） | **20 / 40（50%）** |
| top5 命中率 | 0 / 40（0%） | **35 / 40（88%）** |

### 3.3 归因实验：饱和到底是"模型问题"还是"语料问题"

用 `rerank`（基础版）做受控实验，第 4 组是决定性证据：

| 候选池 | 分数跨度 |
|---|---|
| 纯真实候选（20 条，全是无人机内容） | 0.000007 |
| 真实 20 条 + 4 条跨领域噪音 | **0.529628**（0.47 ~ 1.0） |
| 仅 4 条跨领域噪音 | 0.529265 |

**基础版 rerank 的分数主要反映"领域相关性"，而非"对具体问题的精确匹配度"**：
候选池全是同一个领域时，它认为"都相关"，于是全打高分。

而我们做的是**单一领域的客服知识库**——候选池天然同质。
所以这个模型在我们的场景里**必然失效**，与语料扩到多大无关。
换 `rerank-pro` 后，同质候选池的分数同样能拉开到 0.998 跨度。

### 3.4 两个模型的 API 返回结构不同（易踩）

```jsonc
// rerank
{"results": [{"index": 0, "relevance_score": 1.0}, ...]}

// rerank-pro ← 不回 index！
{"results": [{"document": "<传入的原文>", "relevance_score": 0.9995}, ...]}
```

`rerank-pro` 需要用 `document` 原文反查候选下标（代码见 `verify_scale.py:glm_rerank`）。
直接复用旧解析逻辑会 `KeyError: 'index'`。

### 3.5 可用模型名核查

| 模型名 | 状态 |
|---|---|
| `rerank` | ✅ 可用（但区分度差，不推荐） |
| **`rerank-pro`** | ✅ **可用，推荐** |
| `rerank-2` / `rerank-large` / `bge-reranker-v2-m3` | ❌ 模型不存在（错误码 1211） |

## 四、检索参数标定结果

### 4.1 全链路配置

```
query
  → 混合检索 top20
      ├ 稠密向量（GLM embedding-3, 2048 维, COSINE）取 20
      └ BM25 全文（Milvus 中文分析器）取 20
      → RRF 融合
  → rerank-pro 重排
  → 取 top-N（见 4.3）
```

### 4.2 候选数：越多越好（反直觉）

| 候选数 | 分数跨度 | 期望文档排名 |
|---|---|---|
| **top20** | 0.997966 | #1 |
| top10 | 0.981347 | #1 |
| top5 | 0.163890 | #1 |
| top3 | 0.000578 | #1 |

候选池越大，rerank 的分数分布越有参照系（有足够的"低分对照组"）。
**结论：不要吝啬候选数，top20 是合适的。**

### 4.3 top-N 取值：收益递减点在 top5

40 条 RAG 类评估问题的命中率：

| top-N | 命中 | 命中率 |
|---|---|---|
| top1 | 20 / 40 | 50% |
| top3 | 29 / 40 | 72% |
| **top5** | **35 / 40** | **88%** |
| top8 | 36 / 40 | 90% |
| top20 | 37 / 40 | 92% |

**注意**：3 条"未命中"的题（`eval-028` 天气、`eval-029` 游戏推荐、`eval-034` RTK 原理）
是评估集**特意标注为"知识库未覆盖"**的，检索不到是**预期行为**。

剔除这 3 条后，真实可答问题的命中率：

| top-N | 命中率 |
|---|---|
| top5 | **35 / 37 = 94.6%** |
| top8 | **36 / 37 = 97.3%** |

**建议取 top5**（或保守取 top8）。理由：
- top5 → top8 只多覆盖 1 条，却要多送 60% 的上下文，**上下文预算不划算**
- 4.4 会说明：多召回的片段未必能用，反而稀释生成质量

### 4.4 阈值：能筛"跨域"，不能筛"领域内无答案"

按评估集标注的 `expected_hit_level` 分组，看各组 top1 分数：

| level | n | min | 中位 | max |
|---|---|---|---|---|
| `high` | 20 | 0.3775 | 0.9972 | 0.9998 |
| `medium` | 13 | **0.0851** | 0.9149 | 0.9975 |
| `none` | 2 | **0.0001** | 0.4089 | **0.8176** |
| `partial` | 5 | 0.8933 | 0.9669 | 0.9944 |

**分组存在重叠**：`medium` 组最低 0.0851 低于 `none` 组最高 0.8176。
所以**绝对阈值无法判断"知识库是否有答案"**。

但两类情况可以区分开：

| 情况 | 实例 | top1 分数 | 可用手段 |
|---|---|---|---|
| **完全跨域**（问到知识库外） | `eval-028`「今天北京的天气怎么样」 | **0.000142** | ✅ 硬阈值 `top1 < 0.01` → 直接兜底，不调生成模型 |
| **领域内但无答案** | `eval-034`「RTK 是什么原理」 | 0.9627 | ❌ 阈值区分不了 → 交给生成阶段诚实说明 |
| 领域内且部分覆盖 | `eval-029`「推荐无人机模拟飞行游戏」 | 0.8176 | ❌ 同上 |

**参数建议**：

```
if top1_score < 0.01:        # 完全跨域，硬兜底
    → 直接回复「知识库未覆盖该问题」，不调用生成模型
elif top1_score < 0.5:       # 模糊区（可选：交 LLM judge 复核）
    → 生成时明确提示「资料可能不足」
else:
    → 正常生成，附引用
```

**"领域内但无答案"是本方案的真实短板**（详见第六节）。

## 五、命中质量个案（供后续优化定位）

三类表现不佳的查询：

| 用例 | 问题 | top1 分 | 期望文档排名 | 归因 |
|---|---|---|---|---|
| `eval-010` | 飞机上要不要贴二维码？ | 0.8808 | **#9** | 口语说法，与原文「实名登记」零字面重合 |
| `eval-039` | 限高 | 0.7058 | **#6** | 超短查询（2 字），语义不足 |
| `eval-040` | 无人机黑飞会有什么后果？ | 0.8808 | **#4** | 口语术语，与法规原文零重合 |
| `eval-036` | 无人机的噪音大不大？ | **0.0851** | #2 | 低分但命中，说明**低分≠无关** |
| `eval-015` | 拍视频画面卡卡的 | 0.3775 | #2 | 同上 |

**结论**：`eval-036`（0.0851 命中）与 `eval-029`（0.8176 未覆盖）形成鲜明对比，
再次印证 **绝对阈值不可作为"有/无答案"的判据**。

而三条口语/超短查询（010 / 039 / 040）排名靠后，说明 **Query 改写仍有明确价值**——
它能把这些查询"翻译"成与语料用词对齐的表述，从而提升召回排序。

## 六、遗留问题与下一步

### 6.1 必须解决的

1. **"领域内但无答案"无法识别**
   例：问「RTK 原理」，知识库只有"机型支持 RTK"的表述，没有原理说明。
   rerank 打 0.9627 高分，阈值筛不掉，生成模型可能据此编造。
   → 建议：生成 prompt 里强制「只依据给定材料作答，材料不含该信息时明确说明」，
     或引入 LLM judge 做二次裁决（成本 +1~3 秒）。

2. **评估集标注粒度需细化**
   当前只标 `expected_doc_ids`（文档级），不标 chunk。
   扩语料后出现新的等价答案来源（如 `model-mini-301` 也含重量信息），
   标注未覆盖 → 评估结果会低估实际召回水平。

3. **第三方语料许可**
   源仓库无 License，仅本地学习使用，**不可随项目分发**。
   若要长期留存，建议替换为 CC 授权来源（如中文维基百科）或自建。

### 6.2 可选的优化

4. **Query 改写**：针对口语/超短查询（010/039/040），用 LLM 改写成规范表述后再检索
5. **BM25 阈值**：实测正常查询 BM25 分 2.98~5.38、噪音 1.498，仍有区分度，可作为辅助信号
6. **语料继续扩充**：当前 934 chunk，可再补中文维基、CAAC 公开文件；扩量后需复测本报告参数
