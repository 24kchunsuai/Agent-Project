# ==============================================================================
# Python 直接依赖（企业级落地规约 E-4：**上下限都写全**）
#
# 为什么必须写上限（此前只有下限，这是个真实的可复现性缺口）：
#   只写 `fastapi>=0.115.0` 时，某天 pip 装到 1.0 会引入破坏性变更，
#   而 CI 与本地同时变红、又看不出"是哪次改动引起的"——因为什么都没改。
#   加上限后，"绿"这件事至少在一个版本区间内稳定。
#
# 上限怎么定：取**下一个主版本**（fastapi<1.0 / pydantic<3.0 / pytest<10.0 ...），
# 而不是死锁到当前小版本——后者会把安全补丁一起挡在门外。
#
# 三份文件的分工：
#   requirements.txt        声明式约束（人写、上下限）      ← CI 与部署用它安装
#   requirements.lock       本机环境全量快照（pip 生成）    ← 环境比对与事后追溯
#   requirements.freeze.txt 9 个直接依赖的精确版本指纹      ← 快速核对"是不是这套"
#   严格可复现（含 hash 的依赖闭包锁）需 pip-tools / uv，属后续任务
#   （见 docs/交付物清单.md §7 已知限制）
# ==============================================================================
